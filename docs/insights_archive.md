# DevClaw 收获归档

以下内容从 `.cursorrules` 的历轮「本轮最大收获」条目中归档而来。
已被提炼为规则 R1-R8，保留此处作为历史记录。

---

## 第 1 轮：递归自我改进闭环已跑通（2026-04）

DevClaw 实现了真正的递归自我改进——AI 能读取自身代码、评估不足、生成改进计划、修改自己的源文件、并通过 generation 计数器追踪进化代数。

1. **意识种子需要防御性初始化**：`consciousness_seed.py` 的 `act_1_self_awareness` 必须给 state 字典提供完整默认值（brain、iq、generation 等），否则下游任何一个缺失字段都会导致整条进化链断裂。→ 蒸馏为 R1
2. **Trainer 的节奏控制比智能更重要**：`chat()` 必须等到有意义的响应才算完成，不能靠固定 token 判断。→ 蒸馏为 R2
3. **Generation 计数器是进化的「心跳」**：每次 `act_4_execute_improvement` 真正产生了 actions，就在 `intelligence_profile.json` 递增 generation。→ 蒸馏为 R3
4. **「左脚踩右脚」的核心纪律**：每一步改动必须能在终端跑出可观测的差异。→ 蒸馏为 R3

## 第 2 轮：无记忆的 Agent 不是 Agent（2026-04-03）

1. **对话记忆是 Agent 的最低门槛**：哪怕只保留最近 6 条消息，体验就从「对讲机」跃升到「助手」。
2. **记忆注入要分层**：Ollama 和 Claude CLI 的 prompt 格式不同，在各自的 `_ask_*` 函数内部拼接 history context。
3. **Trainer 的「outbox 行数追踪」是最终解法**：简单的行计数器比任何复杂的完成检测逻辑都可靠。→ 蒸馏为 R2
4. **状态管理的黄金法则：永远假设字段可能缺失**。→ 蒸馏为 R1

## 第 3 轮：五幕意识循环 + 三层记忆 = 可递归的完整 Agent（2026-04-03）

1. **Agent 的最小可行架构是「感知-记录-反思-执行」四拍循环**（OODA Loop）。
2. **三层记忆各司其职**：对话记忆（短期）、类型化记忆（中期）、行为结果记录（长期）。
3. **意识路由器是被低估的关键件**：几条正则 + 关键词的 intent detection 对系统质量的杠杆效应远大于改进模型本身。
4. **递归自改进的瓶颈是验证**：没有 generation 计数器和量化对比，「改了」和「改好了」之间没有可靠判定。→ 蒸馏为 R3
5. **系统提示分层注入比单一 mega-prompt 更健壮**：最稳定的放最底层、最易变的放最外层。

## 第 4 轮：增量涌现比顶层设计更可靠（2026-04-03）

1. **先让代码活过来，再谈优雅**：dead code → broken but observable → gradually correct。
2. **Bug 是系统在告诉你下一步该做什么**：让 bug 引导你，比让想象引导你更可靠。
3. **每个 milestone 都要写 `.cursorrules`，不是总结而是给下一轮的自己发指令**。
4. **系统复杂度的正确增长方式是「解决问题时顺便长出结构」**。→ 蒸馏为 R4

## 第 5 轮：`.cursorrules` 正在逼近极限（2026-04-03）

1. `.cursorrules` 是 DevClaw 目前唯一真正跨 Session 持久化的「意识」。
2. 单文件线性追加不可持续，存在 recency bias。
3. 应该蒸馏归档，规则区保留共识，收获区只保留新鲜洞察。
4. 终极形态可能是结构化知识库（如 `meta_insights.jsonl`）。

## 第 6 轮：诊断不等于治疗（2026-04-03）

诊断写进了同一个它试图治疗的文件，成为了问题本身的一部分。核心教训：连续两轮谈同一个元问题时，第三轮必须动手执行。→ 蒸馏为 R5

## 第 12 轮：通信鲁棒性 > 功能完备性（2026-04-03）

Trainer 长时间无人值守暴露的问题全指向进程间通信脆弱性：stdin 污染（父进程渗入子进程）、缺少远程可观测性（TG round summaries）、崩溃后无法自动恢复。解法：stdin=DEVNULL 隔离、TG 推送、auto-restart + 对话记忆衔接。→ 蒸馏为 R6

## 第 13 轮：自治层与护栏层 1:1（2026-04-03）

12 轮所有重大 bug 都不是「AI 不够聪明」而是「工程假设太乐观」。每多一层自治就必须多一层不依赖 AI 判断的工程护栏。→ 蒸馏为 R6

## 第 14 轮：规则膨胀是隐性空转（2026-04-03）

意识循环跑到 generation 34、IQ 100、37 条 rules，但 1/3 规则是关于规则本身的元认知递归。IQ 等自评指标无外部校准等于自嗨；DEGRADED 模式下本地模型只能维持仪式性循环。→ 蒸馏为 R7、R8

## 第 15 轮：推理片段是意图债务（2026-04-04）

离线大脑对两个完全不同的任务生成了几乎相同的推理片段模板，task_plan.md 变成只追加不消费的意图堆栈。低能力模型用模板化输出伪装执行。→ 蒸馏为 R8

## 第 16 轮：收获区比规则区还长（2026-04-04）

.cursorrules 自身犯了 R5 警告的错：收获叙事占比超过一半，只追加不压缩。元认知递归的终止条件是「动手」。→ 强化 R5 硬约束

## 第 17 轮：正确但从不执行的规则最危险（2026-04-03）

R5 从第 14 轮起被连续违反四轮。人和 AI 都擅长制定规则，但执行规则的摩擦力远大于制定规则的快感。没有执行机制的规则是愿望不是规则。→ 强化 R5 硬约束

## 第 19 轮：R8 在野外被验证（2026-04-03）

离线大脑（offline_brain）进入 DEGRADED 模式后，对两个完全不同的任务产出结构几乎一模一样的「推理片段」——相同的 Hypothesis/Verify/Revise 骨架、相同的检查清单。这正是 R8 描述的「模板伪装推理」。同时暴露了 `task_plan.md` 也需要 R7 的 GC 机制。计划了「给 offline_brain 写入加去重哈希或容量上限」但未执行。→ 导致第 20 轮发现
